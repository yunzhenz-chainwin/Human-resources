## 4. 文件格式：Word（.docx）為交付與維護格式

依維護者要求，全套文件自 2026-08-27 起以 Word（.docx）格式保存與交付；文件間引用
一律連到同資料夾的 `.docx`。轉檔前最後一版的 Markdown 原稿完整保留在 git 歷史
（轉檔提交的上一個提交；`git log -- docs` 可查），需要比對或回復時可隨時取回。

同日稍早的清理另移除了下列過期二進位快照，原因如下；曾納入版本控制者皆可自 git 歷史取回：

| 已移除檔案 | 移除原因 |
|---|---|
| `10-系統元件與資料庫使用手冊.docx` | 內容停在 2026-07-16，`.md` 主檔其後已多次大改；本規則原本就明定以 `.md` 為準 |
| `TalentHub_後續規劃_主管報告.docx` | 2026-07 快照，先於結構化評分、綜合分與 ClamAV 等落地，內容會誤導主管；需要簡報版時依 07／12 現況重新產出 |
| `TalentHub_專案時程表.xlsx` | 展示用時程快照（2026-08-04），07 已是完成度唯一主來源 |

要產生列印版或簡報版時，直接以現行 `.docx` 另存或裁剪，不要回收上述舊快照。

## 5. 整合後的主來源規則

同一主題出現在多份文件時，依下表判斷哪裡才是最後答案：

| 主題 | 主來源 | 其他文件只保留什麼 |
|---|---|---|
| 現在完成到哪、何時上線 | 07 | 01 保留原始規劃；12 只保留未完成工作 |
| 實際 API schema／錯誤碼 | FastAPI OpenAPI＋程式 | 05 保留導覽與關鍵契約；13 保留面試專用契約 |
| 實際資料庫欄位 | SQLAlchemy models＋Alembic | 03 保留概念設計；10 保留維運清單 |
| 個資、同意、保存、遮罩 | 08 | 專題文件只描述落地操作並連回 08 |
| 面試題如何產生 | Gemini 專題 Runbook | 13 只處理評分、提交與盲評 |
| 面試如何評分 | 13 | 05／06／08／10 只保留端點、畫面、安全與維運摘要 |
| 媒合策略與限制 | 11 | 小樣本文件只保留測試操作與指標定義 |
