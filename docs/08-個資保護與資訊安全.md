# 08. 個資保護與資訊安全

**文件版本**：v1.1（2026-08-04）
**定位**：本系統儲存大量求職者個人資料，屬《個人資料保護法》規範之「非公務機關蒐集、處理及利用個資」情境。本文件為系統設計依據，**正式上線前建議由公司法務（或外部顧問）覆核**。

---

## 1. 法遵框架（個資法對應）

| 法規要求 | 系統對應設計 |
|---|---|
| 蒐集須有特定目的與法定要件（§19） | 目的明確：招募甄選與人才庫管理（特定目的代號以主管機關公告為準，如「人事管理」類）；來源為當事人主動投遞或平台合法取得 |
| 告知義務（§8 直接蒐集／§9 間接蒐集） | 求職者於 104/1111 投遞時已同意平台條款供企業會員使用；**企業自建庫長期留存屬延伸利用**，系統支援告知信發送與狀態追蹤（見 §2） |
| 目的內利用（§20） | 資料僅用於招募媒合；系統無對外分享介面；匯出功能限 HR 且全程稽核 |
| 當事人權利：查詢、複製、補正、停止利用、刪除（§3、§11） | 提供單筆匿名化/刪除功能與處理 SOP（見 §3） |
| 安全維護義務（§27） | 存取控制、加密、稽核、備份（見 §4–§6） |

> ⚠️ 注意：104/1111 會員條款通常限制「下載之履歷僅得用於本次招募目的」。**將履歷長期留存於自建人才庫，須以告知/取得同意來補強適法性**——這是本系統把 `consent_status` 設為一級欄位的原因。

## 2. 同意與告知管理

### 2.1 `consent_status` 狀態定義

| 狀態 | 意義 | 系統行為 |
|---|---|---|
| `platform` | 僅平台投遞授權（初始匯入狀態） | 可用於**該次**招募配對；建議在保存期限內完成告知 |
| `notified` | 已寄送告知信（含退出連結/回覆方式） | 正常使用；信件寄送記錄於活動紀錄 |
| `consented` | 已明確同意納入人才庫長期留存 | 正常使用，`retention_until` 依同意條款設定 |
| `withdrawn` | 當事人拒絕/撤回 | **立即停止配對**（gate 排除），依 SOP 匿名化 |

### 2.2 告知信要點（範本要素，法務定稿）

公司名稱與聯絡窗口／蒐集目的（招募甄選與未來職缺媒合）／個資類別（履歷所載基本、學經歷、聯絡資訊）／
利用期間（至保存期限）、地區（台灣）、對象（本公司 HR 與用人單位）、方式（電子檔於內部系統）／
當事人依個資法 §3 得行使之權利與行使方式／不同意之影響（僅本次招募後即刪除）。

### 2.3 面試同意書

候選人由公開頁本人填寫時，頁面會讀取目前生效的版本化「個資蒐集告知暨同意書」，送出資料必須同時帶回該 notice 的 ID 與版本；若條款已更新，舊表單會被拒絕並要求重新閱讀。系統保存同意時間、管道與版本。其他來源進入面試階段時，仍應由候選人簽署同意書，再由 HR 完成存證。撤回會關閉該人才所有仍有效的同意紀錄、把人才狀態同步為 `withdrawn`，並立即排除正式媒合。

## 3. 保存期限與當事人請求 SOP

- 預設保存 **2 年**（`candidate.retention_years`，Admin 可設定 1–20 年，單筆人才可覆寫）。目前起算點為明確同意時間；尚無明確同意時以建檔時間起算。一般聯繫或編輯**不會自動展延**，避免未經重新同意而無限延長。
- 到期前通知與續存同意仍待 Email／通知流程完成；未完成前由 IT 以後台 dry-run 清單交由 HR 覆核。
- 到期清理目前採**完整刪除**：人才主檔、關聯招募資料、履歷資料與照片一併清除；檔案刪除失敗會留在 durable outbox 重試。worker 預設關閉，只有明確啟用或執行才會刪除。
- 撤回同意會立即停止媒合，並把保存期限設為當日，使資料可進入下一次清理；是否立即執行清理仍須依公司核准 SOP。
- **當事人請求刪除 SOP**：收到請求 → HR 核對身分與請求範圍 → 由授權人員預演影響 → 核准後執行清理 → 確認 audit 與檔案 outbox 完成 → 回覆當事人。回覆期限與例外保留義務須由法務定稿。

## 4. 存取控制（RBAC + 欄位遮罩）

| 資料 / 操作 | Admin | HR | 部門主管 |
|---|---|---|---|
| 人才完整聯絡資訊（電話/Email） | ✔ | ✔ | 遮罩（`0912***678`） |
| 地址／生日 | ✔ | ✔ | 不提供 |
| 期望薪資 | ✔ | ✔ | ✔（可設定遮罩） |
| 履歷原始檔下載 | ✔ | ✔（稽核） | ✖（需要時由 HR 提供） |
| 人才庫全庫搜尋 | ✔ | ✔ | ✖（僅見自己職缺的推薦名單） |
| 匯出名單 | ✔ | ✔（稽核+浮水印） | ✖ |
| 刪除 / 匿名化 | ✔ | 申請（Admin 執行）或雙人確認 | ✖ |
| 需求單核准 | ✔ | ✔ | ✖（僅提出與檢視） |
| 系統設定 / 帳號管理 / 稽核日誌 | ✔ | ✖ | ✖ |

原則：**最小權限**＋主管「看得到適配度、拿不到聯絡方式」——聯繫候選人統一由 HR 執行，兼顧個資與招募流程紀律。

## 5. 稽核（Audit）

必記錄事件（`audit_logs`，含 who/when/what/ip）：

- 登入成功/失敗、登出；帳號級連續失敗計數達門檻即**自動過期鎖定**（`users.failed_login_count` / `locked_until`），鎖定期間回 429 + `Retry-After`
- refresh token 重用偵測（撤銷整個 token family、連動令既有 access token 失效時記錄）
- **檢視人才詳情**（個資讀取軌跡——查外洩時的關鍵證據）
- 建立/修改/刪除/匿名化人才；下載原始履歷檔；匯出（含筆數與條件）
- 需求單核准/退回；權限與角色變更；系統參數變更

保留 ≥ 3 年，按月分區；Admin 後台可依人/動作/期間查詢與匯出。

## 6. 技術性安全措施

| 面向 | 措施 |
|---|---|
| 傳輸加密 | 全站 HTTPS/TLS 1.2+（內網用企業 CA 或自簽憑證佈署至員工電腦） |
| 儲存加密 | 磁碟層加密（LUKS/BitLocker）；備份檔加密後異地存放 |
| 密碼 | scrypt 雜湊；長度 ≥ 12；IT 重設／管理員設定密碼後 `must_change_password` 生效，須先改密才能繼續使用；帳號級連續失敗計數 + 自動過期鎖定（達門檻回 429 + `Retry-After`）；未知帳號亦跑 dummy hash 以消除 timing 枚舉 |
| Token | JWT access 15 分鐘 + refresh 7 天輪替；密碼變更／重設令既有 access token 失效（`users.tokens_valid_after`）；refresh token 具重用偵測（撤銷整個 token family 並連動 access token 失效 + 稽核）；提供 `POST /auth/change-password`、`POST /auth/logout`，前端登出會先 best-effort 撤銷伺服器 refresh token 再清除本機狀態 |
| 上傳安全 | 副檔名/MIME 白名單、大小上限、ClamAV 掃描（**非 dev 環境一律 fail-closed**：掃描不可用即拒收）、解析/OCR 移至 threadpool 避免阻塞事件迴圈、公開上傳加 per-IP 限流、檔案存 MinIO 不落 Web 根目錄、下載一律預簽名短效網址；THR1 履歷 PDF 需 HMAC 簽章才自動信任，未簽章者轉人工審核 |
| 應用安全 | ORM 參數化（防 SQL injection）、輸出轉義（防 XSS）、CSRF（SPA 用 Bearer 天然緩解）、依賴套件掃描（`pip-audit` / `npm audit` 進 CI） |
| 網路 | 系統僅開放內網存取；DB/Redis/MinIO 不對外開 port；管理埠限跳板機 |
| LLM 選配 | Gemini 預設關閉；面試題 prompt 僅使用職缺條件與結構化工作證據白名單（如職稱、年資、技能），不傳姓名、聯絡資訊、地址、生日、公司／學校名稱或自由文字經歷；啟用前仍須完成個資影響評估與核准 |

**已完成的程式／部署設定強化（正式環境仍須逐項驗證）**：

- 容器以**非 root** 使用者執行；正式環境 API 僅綁 **loopback**（對外一律由 nginx 反代），MinIO 亦綁 loopback。
- 正式環境關閉 `/docs`（連同 `/redoc`、`/openapi.json`）；nginx 加上安全標頭（`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy`、`Content-Security-Policy`）。
- 真實用戶端 IP 經反向代理標頭取得（`X-Forwarded-For`、uvicorn `--proxy-headers`），使限流與稽核記錄正確來源。
- `/health` 實際檢查 DB 連線（`SELECT 1`）而非僅回 200；CI 加入 `pip-audit` 相依套件弱點掃描；已移除版控內的 `cloudflared.exe`。

**仍待處理（維運／決策）**：

- 正式 HTTPS／反向代理／WAF 佈署與憑證管理；
- 自動加密備份與定期還原演練；
- 集中式監控／log 平台（告警與外洩追查）；
- 多因子驗證（MFA）；
- refresh token 改以 httpOnly cookie 存放（降低 XSS 竊取風險）。

## 7. 備份與災難復原

- PostgreSQL：每日 `pg_dump` 全備 + WAL 歸檔；MinIO：每日同步至 NAS/異地
- 保留 30 天；備份檔加密
- **每半年還原演練一次**（沒演練過的備份等於沒有備份）
- 目標：RPO ≤ 24 小時、RTO ≤ 4 小時

## 8. 事件應變（個資外洩）

1. 發現（稽核告警/通報）→ 立即停用相關帳號、保全稽核證據
2. 4 小時內通報：資訊負責人 + HR 主管 + 管理層
3. 影響評估：外洩範圍（筆數/欄位）、原因
4. 依個資法 §12 評估**通知當事人**義務與方式；必要時知會主管機關
5. 事後檢討：修補 + 稽核規則補強 + 記錄存檔
