# Gemini 客製化面試題目：預覽與導入規格

> 這份文件是「預覽版」，目前不會呼叫 Gemini，也不會把履歷資料送到外部服務。現有 TalentHub 已有可追溯的規則式題目產生器，可先用它確認畫面與流程，再切換 Gemini。

## 目前畫面應呈現的兩階段

### HR 初談（所有候選人相同）

固定 5 題，確保公平與可比較性。題目、追問方向和評分欄位固定；HR 只需要填寫回答、觀察與 1–5 分。主管可以讀取 HR 的問答，但不能修改 HR 紀錄。

### 部門主管面談（依職缺與履歷客製）

固定產生 5 題，但題目內容以「職缺需求 + 已核准的履歷事實 + 選定人格特質」為依據。每題都顯示：

- 設計依據（例如：職缺必備技能、最近一份工作）
- 提問目的
- 建議追問
- 來源與產生方式（規則式／Gemini 草稿／人工修改）

HR 與主管雙方都能讀取完整問答與進度；只有該階段的紀錄者能編輯自己的回答與評分。

## 預覽範例（不呼叫 Gemini）

輸入資料（已去識別化，只保留工作相關欄位）：

```json
{
  "job_title": "企業客戶經理",
  "required_skills": ["B2B 業務", "CRM", "提案簡報"],
  "candidate": {
    "current_title": "客戶成功經理",
    "total_years": 6,
    "skills": ["B2B 業務", "Salesforce", "提案簡報"],
    "latest_experience": "負責 SaaS 企業客戶導入與續約"
  },
  "traits": ["主動積極", "溝通表達"]
}
```

預覽會顯示類似下列的主管題目：

1. 你曾負責 SaaS 企業客戶導入與續約，請說明一個最棘手的 B2B 客戶案例，以及你如何界定問題、推進決策並量化結果？
   - 依據：最近一份工作／B2B 業務
   - 目的：確認客戶經營、問題拆解與結果導向
   - 追問：若客戶仍未續約，你會先檢查哪三個訊號？

2. 這個職位需要使用 CRM 管理商機。請分享你用 Salesforce 或其他 CRM 建立管道預測的實例，如何確保資料品質？
   - 依據：職缺必備技能 CRM + 履歷技能 Salesforce
   - 目的：驗證工具熟練度與流程紀律
   - 追問：遇到業務不更新資料時，你會怎麼處理？

3. 面對需要跨部門協作的提案簡報，你如何讓產品、技術與客戶對成功標準達成共識？
   - 依據：職缺技能提案簡報 + 人格特質溝通表達
   - 目的：確認溝通結構與協作方式
   - 追問：若兩個部門的優先順序衝突，你如何推進？

題目必須標示「可由面試官編輯」，人工修改後保留原始草稿、修改者與時間，方便稽核與公平性比較。

## Gemini 導入方式（確認後才實作）

後端新增 `GEMINI_API_KEY` 與可選設定：

```text
GEMINI_API_KEY=只放在後端環境變數，不放前端、不提交 Git
GEMINI_MODEL=gemini-2.5-flash
GEMINI_ENABLED=false
GEMINI_TIMEOUT_SECONDS=20
GEMINI_MAX_OUTPUT_TOKENS=1200
```

API key 不需要提供給我或寫入聊天內容。部署時請放在主機的 `.env`、Docker secret 或 Windows 服務環境變數，並限制只有後端程序可讀；前端只能呼叫 TalentHub 後端，不能直接呼叫 Google API。

建議流程：

1. 先由現有規則式產生 5 題，立即可用且可測試。
2. 若 `GEMINI_ENABLED=true`，後端將「去識別化、工作相關」欄位送 Gemini 產生草稿。
3. 後端驗證回傳 JSON schema、題數必須為 5、不得出現姓名／Email／電話／地址／年齡／性別等 PII 或受保護特徵。
4. 驗證失敗、超時或沒有 API key 時，自動回退規則式題目，不影響面試流程。
5. 儲存 prompt 版本、模型、輸入摘要 hash、輸出、人工修改紀錄；不要儲存原始 PII 到 Gemini log。

## 建議的 Gemini 回傳格式

```json
{
  "questions": [
    {
      "question": "...",
      "purpose": "...",
      "follow_up": "...",
      "trait": "溝通表達",
      "evidence": ["職缺：提案簡報", "履歷技能：Salesforce"],
      "confidence": 0.82
    }
  ],
  "warnings": [],
  "prompt_version": "interview-v1"
}
```

`confidence` 只用作人工覆核提示，不得直接變成候選人分數。題目本身也不應推測人格或家庭、健康、年齡等非工作因素。

## 實作前驗收畫面

在正式啟用 Gemini 前，建議先加入「題目預覽」模式：選擇一位候選人、職缺與人格特質後，顯示規則式結果與 Gemini 草稿左右對照；面試官可逐題接受、編輯或退回。按下「套用至主管面試」才寫入面試紀錄。
